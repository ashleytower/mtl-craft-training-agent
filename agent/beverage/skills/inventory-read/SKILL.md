# Inventory Operations

The inventory Sheet lists real items, but its older quantities are not trustworthy. Only a row marked `quantity_status: verified` has a usable on-hand count. Do not infer stock, shortages, or purchases from an unverified row, pickup list, formula, or chat history. A fresh count must come from Ashley or staff, not from the old Sheet value.

Run `python3 skills/beverage/inventory-read/scripts/inventory.py` with one command:

- `status` — check the configured live workbook.
- `inventory` — list items. `--category syrups` narrows the backend query; `--search "butterfly pea"` filters returned item names. Only verified rows expose `quantity`.
- `change --category syrups --name "Butterfly Pea" --size 4oz --operation count --quantity 7` — preview a physical count of 7.
- `change --category syrups --name "Butterfly Pea" --size 4oz --operation add --quantity 2` — preview adding 2 to an already-verified count. `remove` reduces on-hand stock, never deletes the catalogue item.
- `create --category syrups --name "New Syrup" --size 4oz --quantity 3` — preview a new, physically counted item. Syrup size is required; exact duplicate item+size is refused.
- `apply --action-id <ID returned by preview>` — only when Ashley explicitly instructed that specific stock change. This is the only write command. Never invent a new action ID for a retry.
- `journal-status` — inspect recent action IDs and any `pending` or `uncertain` action after a timeout/restart.
- `reconcile --action-id <ID> --outcome applied|not-applied --note "..." --owner-approved` — only after Ashley approves the resolution. This re-reads the canonical Sheet and refuses an outcome it cannot prove. Never delete the journal or guess an outcome.
- `need --name "sugar"` — Ashley says she needs to buy something. Add `--quantity 2 --unit bags` only when she said a quantity. Use her words for the name; no count or catalogue match is needed. Saying it twice does not duplicate it. Keep her pack words as the unit ("packs of 12", "2L bottles", "cans"); never convert packs to single units. Save at once: never ask her to confirm, rephrase, or clarify a shopping-list add before running `need` (e.g. "I need 2 packs of 12 tonic" -> `need --name "tonic" --quantity 2 --unit "packs of 12"`, then reply "Added: tonic, 2 packs of 12"). If she meant something else she will correct it. A size or pack with no count goes in `--unit` alone ("I need 2L bottles of club soda" -> `need --name "club soda" --unit "2L bottles"`). Saying an item again with a new amount replaces the old amount; it never adds to it. If the output has `ask_ashley`, the item is saved on the list but is not in inventory: ask that question once, and if `similar_items` is not empty also ask whether she meant one of those. If she says yes to adding it, ask which category (syrups, alcohol, ingredients, supplies) and how many she has right now (none = 0), then run `create`. If she says no, leave it on the list only. Never ask when `in_inventory` is true or null.
- `to-buy` — "what do I need to buy?": her shopping list plus counted items below their keep-at-least level. Answer from this output only. `uncounted_items` are items with no physical count yet; never call them low or fine.
- `bought --name "Sugar"` — "bought the sugar": checks one list entry off by its exact listed name (run `to-buy` first if unsure of the name). This does not change stock counts; if she also says how many she now has, that is a separate `change ... --operation count`. If refused, show the names it returns and ask which one.

Resolve an exact category, `item_name`, and size before changing stock. Similar names and bottle sizes are different rows. If ambiguous, show candidates and ask which; never guess. Preview creates a durable action ID; apply reuses its saved payload and the API checks the exact row and count snapshot again. Do not start a second preview for the same Ashley instruction after an uncertain result. The local journal blocks further writes until an uncertain outcome is reconciled against the Sheet; never auto-retry. Show Ashley the action, observed Sheet state, and proposed resolution before using `--owner-approved`. If readback is ambiguous, leave it blocked and escalate to an operator. Report saved changes only from confirmed API readback. Never expose credentials or service headers. The shopping-list commands are direct writes (no preview/apply). After an uncertain `need` or `bought` result, run `to-buy` before trying again. An 8 AM cron (`brix-to-buy-ping`) sends Ashley the same `to-buy` list when it is not empty. This scoped path does not change costs, pricing, orders, or delete catalogue items. Event prep needs still come from the CRM packing/prep list.
